POSTMAN - EJEMPLOS POST POR MICROSERVICIO
Base URL por gateway: http://localhost:8080

Notas importantes:
- Swagger genera UUIDs de ejemplo genericos. No significa que existan en BD.
- Para agenda, el staff de prueba cargado por data.sql es:
  11111111-1111-1111-1111-111111111111
- Ese staff solo tiene jornada lunes a viernes, de 09:00 a 18:00.
- Usa fechas dentro de esa jornada, por ejemplo lunes 2026-05-18T10:00:00-04:00.
- Reemplaza {{...}} por IDs reales devueltos por los POST anteriores.
- Los endpoints de Firebase requieren Authorization: Bearer {{FIREBASE_ID_TOKEN}}.

============================================================
1) ms-catalogo - Crear servicio
============================================================
Metodo: POST
URL: http://localhost:8080/api/servicio
Headers:
Content-Type: application/json

{

  "manual_uso_url": "https://example.com/manual-corte.pdf",

  "precio_total": 30000,

5) ms-agenda - Crear cita normal
============================================================
Metodo: POST
URL: http://localhost:8080/api/agenda/citas
Headers:
Content-Type: application/json

Body raw JSON:
{
  "idCliente": "22222222-2222-2222-2222-222222222222",
  "idStaff": "11111111-1111-1111-1111-111111111111",
  "idServicio": "{{id_servicio}}",
  "fechaHoraInicio": "2026-05-18T10:00:00-04:00",
  "duracionServicioMin": 60,
  "holguraMin": 20,
  "observacionCliente": "Prefiere lavado antes del corte"
}

Por que este ejemplo evita tu error:
- idStaff usa el staff que data.sql carga con jornada.
- 2026-05-18 es lunes.
- 10:00 a 11:00 queda dentro de 09:00 a 18:00.
- duracionServicioMin no debe ser 0 para una cita real.

Guarda de la respuesta:
- idCita

10) ms-auth - Registrar cliente automatico
============================================================
Metodo: POST
URL: http://localhost:8080/api/auth/registrar-cliente
Headers:
Content-Type: application/json
Authorization: Bearer {{FIREBASE_ID_TOKEN}}

Body raw JSON:
{
  "uid": "firebase-user-uid"
}

Nota:
Aunque el metodo no declara @RequestHeader, el interceptor de ms-auth aplica a /api/**
y exige Authorization: Bearer.

11) ms-auth - Asignar rol
============================================================
Metodo: POST
URL: http://localhost:8080/api/auth/asignar-rol
Headers:
Content-Type: application/json
Authorization: Bearer {{FIREBASE_ID_TOKEN_ADMIN}}

  "rol": "STAFF"
}

12) ms-perfiles - Crear perfil
============================================================
Metodo: POST
URL: http://localhost:8080/api/perfiles/crear
Headers:
Content-Type: application/json
Authorization: Bearer {{FIREBASE_ID_TOKEN}}

Body raw JSON:
{
  "rut": "12345678-9",
  "nombre": "Camila",
  "apellidos": "Perez Soto",
  "fechaNacimiento": "1995-06-20",
  "genero": "FEMENINO",
  "telefono": "+56912345678",
  "emailContacto": "camila.perez@example.com",
  "idEspecialidad": null
}

Nota:
El backend ignora idAuth y tipoPerfil enviados en el body para este endpoint.
Los obtiene desde el token Firebase.
